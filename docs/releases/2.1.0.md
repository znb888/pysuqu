# pysuqu 2.1.0

This release adds optional C++ acceleration for sampled quantum propagation,
with reusable preparation and the existing QuTiP gate path retained as the default.

## Simulation APIs

- `PreparedPropagation`, `PropagationOptions`, `DriveTerm`, and batch result types
  are available from `pysuqu.qubit`.
- Gate and multi-drive workflows can reuse prepared propagation for states,
  unitaries, channels, and fidelity calculations.
- Solver-facing AWG traces retain transmission-chain and physical-output routing.
- Backends include `qutip`, `qutip_compiled`, `cpp`, `auto`, and the explicit
  approximate `cpp_fast` mode. Unsupported native requests fail clearly;
  `auto` can fall back to compiled QuTiP.

## Native Computation

- Dense, CSR, banded, and fused sparse kernels support sampled controls and
  analytic RF carriers, including nonuniform grids and interpolation orders 0-3.
- Exact interaction frames, invariant blocks, bounded preparation caches, and
  parallel batches reduce repeated work while preserving the specified equation.
- Constant and piecewise-constant problems can use checked Krylov exponential
  actions. Static-collapse Lindblad propagation avoids explicit Kronecker
  Liouvillian construction.
- Result statistics expose backend, integration, representation, and approximation
  information. `cpp_fast` uses a rotating-wave approximation and is never selected
  by `auto`.

## Installation And Compatibility

Python 3.9 or newer and QuTiP 5 are required. Native wheels target CPython 3.9-3.14
on Linux x86_64, Windows AMD64, and macOS arm64/x86_64. A platform-independent
wheel supports QuTiP-only installations. Source builds enable the C++17 extension
with `PYSUQU_BUILD_NATIVE=1`; native source and CMake configuration are included
in the source distribution.

Explicit native propagation currently returns states; use QuTiP or `auto` for
`e_ops` and time-dependent collapse operators. The default callback backend uses
linear interpolation, so compare matching interpolation settings across backends.

This release also fixes measured-T1 thermal excitation analysis and forwards
output-normalization settings consistently to QuTiP.

## Examples And Validation

The [backend guide](../guides/propagation-backends.md) documents installation,
numerical controls, fallback behavior, and reproducible benchmark commands.
[Demo 06](../../demo/demo_06_native_propagation.ipynb) covers RF controls, reusable
state batches, and analytic relaxation checks using synthetic parameters.

Numerical coverage compares native results with analytic rotations and decay,
SciPy integration and exponential actions, and QuTiP. Wheel validation installs
each artifact and checks all six native kernel entry points before running the
real propagation tests. The release workflow also verifies the Python-only wheel,
rebuilds a native wheel from the source distribution, runs public tests, and
executes the tutorial. Benchmark speedups depend on workload and hardware; cold
and repeated timings are reported separately alongside numerical errors.
