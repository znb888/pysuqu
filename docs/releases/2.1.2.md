# pysuqu 2.1.2

This release continues the native simulation work with bounded caches, clearer
backend boundaries, and public signal-processing helpers. The default QuTiP
path and compiler-free installation remain available.

## Propagation And Native Backends

- Added content-owned `PreparedPropagation` input snapshots and optional prepared
  native entry-point compatibility for older extensions.
- Added `DynamicCollapseRate` descriptors. QuTiP preserves callback semantics;
  unsupported native dynamic-rate requests report capability errors and `auto`
  falls back safely.
- Added public C++ backend module import points for loading, execution, plans,
  preparation, results, and Lindblad support while retaining the compatibility
  adapter.
- Added explicit native CPU/PGO build controls and CMake dependency tracking.
  Portable builds remain the default and MSVC rejects unsupported host-only flags.

## Caches And Workflows

- Gate runs support opt-in prepared-context reuse with strict content keys,
  bypassing opaque callbacks and mutable transmission chains.
- AWG generation has an optional bounded `WaveformCache` with copied outputs and
  callable bypass. Touchstone and MIMO response interpolation have bounded
  content-keyed caches with read-only stored arrays.
- Continuous Ramsey, SpinEcho, and CPMG dephasing can batch delay integrations
  through `PreparedFilteredPSD` and `quad_vec`, with a scalar SciPy fallback.
- Added a direct scalar-friendly single-qubit energy sweep entry point.

## Signal Processing

- Added public predistortion design helpers covering derivative bases, sampled
  FIR inversion, ZOH state-space models, discrete propagation, and diagnostics.
  The APIs use explicit synthetic or caller-provided traces and do not embed
  machine-specific workflow data.

## Validation

- Added focused tests for build options, native loader compatibility, input
  ownership, dynamic rates, cache invalidation, gate reuse, PSD batching, sweep
  ergonomics, backend module imports, and predistortion contracts.
- Existing native propagation, structured sparse, Krylov, open-system, gate,
  functional, and regression tests remain part of release validation.
- Release artifacts are checked on CPython 3.9–3.14 for Linux x86_64, Windows
  AMD64, and macOS arm64/x86_64. Examples, benchmark inputs, and notebook
  metadata use portable synthetic values.
